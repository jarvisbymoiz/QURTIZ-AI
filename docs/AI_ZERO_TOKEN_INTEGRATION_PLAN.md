## Decision and reference analysis

AI-Zero-Token is an experimental, single-user local gateway. It stores Codex/ChatGPT OAuth profiles and refresh tokens locally, refreshes them locally, selects a local account, and exposes OpenAI-compatible `/v1/images/generations` plus JSON `/v1/images/edits`. At verified upstream HEAD `d54bd48b0912b3a7cfe3ae41d2809e4e1db98a79`, its image service routes a Free-plan profile through a **private ChatGPT web-image flow only when** `freeAccountWebGenerationEnabled` is explicitly enabled; this setting defaults to false. Other requests use the Codex Responses image tool. The web flow is not an official OpenAI API or a production multi-tenant gateway. [API usage](https://github.com/fchangjun/AI-Zero-Token/blob/d54bd48b0912b3a7cfe3ae41d2809e4e1db98a79/docs/API_USAGE.md), [OAuth source](https://github.com/fchangjun/AI-Zero-Token/blob/d54bd48b0912b3a7cfe3ae41d2809e4e1db98a79/src/core/providers/openai-codex/oauth.ts), [image service](https://github.com/fchangjun/AI-Zero-Token/blob/d54bd48b0912b3a7cfe3ae41d2809e4e1db98a79/src/core/services/image-service.ts), [web-image source](https://github.com/fchangjun/AI-Zero-Token/blob/d54bd48b0912b3a7cfe3ae41d2809e4e1db98a79/src/core/providers/openai-codex/chatgpt-web-image.ts).

**Current strategy:** Qurtiz never handles ChatGPT OAuth. The Windows companion package launches a dedicated local AI-Zero-Token gateway and Qurtiz bridge on loopback. The gateway owns OAuth and local credentials; after real login the companion discovers account-scoped Codex models and selects a compatible image path by capability, with the explicitly opted-in experimental web route available when Codex is unavailable. Plan names do not select the route. Qurtiz cloud receives only the generated image needed for Content Studio storage and non-secret metadata; it never receives, stores or logs ChatGPT access/refresh tokens, Codex auth files, cookies or local gateway credentials. The adapter still accepts a compatible local gateway for development. Do not copy AI-Zero-Token's bundled OAuth client or private web implementation into Qurtiz SaaS.

OpenAI's [official image API](https://developers.openai.com/api/docs/guides/image-generation) is separate from ChatGPT subscription access. The Free-account web route is unofficial and may stop working or exhaust quota at any time. OpenAI's [terms](https://openai.com/policies/terms-of-use/) restrict programmatic extraction and circumvention of protective measures. Show the user this risk before enabling the experimental mode; never label it as official or guaranteed free service.

## Browser-to-local architecture

```text
API Mode (default): browser -> Qurtiz server -> existing configured API provider -> existing visual pipeline

Experimental Local Mode (interactive only):
Qurtiz browser -> Qurtiz server: prepare brand-aware image brief + short-lived one-use ticket
Qurtiz browser -> 127.0.0.1 companion -> local gateway /v1/images/generations
Qurtiz browser -> Qurtiz server: generated image + ticket
Qurtiz server -> existing visual storage, logo composition, DB and UI update
```

The Vercel server cannot call a user's `localhost`. The browser must call loopback directly, subject to browser Local Network Access permissions and CORS; behavior differs across browsers. No cloud tunnel is assumed. The companion must be running on the same device as the browser, and interactive image generation cannot continue after that browser closes. Background bulk jobs stay on API Mode or fail honestly with a clear unsupported-mode message. [MDN local network access](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Local_network_access), [Chrome local network guidance](https://developer.chrome.com/blog/local-network-access).

### Companion trust boundary

- Listen on `127.0.0.1` only; reject unexpected `Host` headers/DNS rebinding and non-allowlisted `Origin` values. No wildcard CORS, network listener or cloud relay.
- Pair browser to companion automatically using a random local secret. It remains in the local browser and companion only. Never submit it to a Qurtiz server action, log, URL, or analytics payload. A compromised browser extension/device can still access it; document that risk.
- Proxy only health/model discovery (if supported) and OpenAI-compatible image generation/edit paths. Enforce method, content type, request/response size, timeout, concurrency and rate limits. No arbitrary URL proxy or account-management endpoint.
- Upstream gateway URL must resolve to loopback; companion rejects redirects and non-loopback destinations. OAuth, account selection, refresh, logout and upstream quota handling remain local to the upstream gateway.
- Qurtiz companion errors preserve upstream status/category without leaking headers, secrets or full upstream response bodies.

### Provider/model abstraction

Use an image-source boundary with a `generate` result normalized to one bounded image plus model/error metadata. API Mode uses existing `generateImage`; local mode uses a browser-side OpenAI-compatible request. Both feed shared visual brief and persistence helpers (`prepareExternalVisual`, `persistExternalVisual` for an external transport). Free Mode omits `model` and lets the local gateway choose its supported image default; no hard-coded Qurtiz image model. A future officially supported delegated OAuth/API can replace the transport while reusing brief creation, logo composition, visual persistence and Content Studio records.

### Persistence and isolation

Keep `workspace_ai_config` unchanged. An additive preference table stores only `(workspace_id, user_id, image_mode, legacy_model_id, updated_at)`; absence means `api`. The legacy model field is ignored by the redesigned Free Mode and can be removed in a later migration. Unique workspace/user and membership FK. Browser roles cannot access it directly; server actions validate authenticated membership. No ChatGPT tokens, local pairing secret, session data, OAuth state or gateway credentials in Postgres. Local browser storage is namespaced by Qurtiz user and workspace; disconnect clears that local secret and resets preference. A member's local mode cannot be used by a different member or background job.

### Errors and quotas

Distinguish companion offline, browser local-network permission/CORS denial, pairing failure, upstream auth/reconnect, unsupported model, quota/rate limit, timeout, invalid/oversized image, and Qurtiz persistence failure. Never mark generation successful until the server verifies and saves the image. No automatic fallback to a paid API call. Quota estimates belong to the local gateway and can be unavailable; no fabricated remaining count. Bound retries and avoid permanent loading.
