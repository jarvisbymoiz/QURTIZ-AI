# Image generation pipeline

Content Studio saves the Visual Prompt on the content item. `buildVisualGenerationBrief` uses it as the primary creative direction, then adds relevant verified post, slide, Brand Brain, memory and generation-reference context. Empty prompts fall back to the hook and then the topic. The Master AI Prompt instruction uses the same brief as its factual design foundation; its external-tool output may be longer and is not sent verbatim to the configured image model.

`generateVisual` resolves the workspace image provider and model, downloads up to four Brand Brain avatar/reference assets, and passes the brief through `generateImage`. Uploaded post media is for publishing, not implicitly a generation reference. Provider adapters attach only supported references and parameters. The real brand logo is composited after image generation. All resulting images follow the existing PNG storage and preview path. Reel video upload and publishing remain separate from image generation.

Cloudflare Workers AI model input schemas are read from the account's official `/ai/models/schema` endpoint and cached for one hour. This determines optional numeric settings, negative prompt, reference fields and multipart transport without a model-name list. If schema discovery fails, the adapter sends a plain JSON prompt and surfaces the provider's response. Gemini receives inline image references and a requested aspect ratio. OpenAI-compatible providers try `/images/edits` with one generation reference and fall back to `/images/generations` only when edits are unavailable. Further reference support varies by gateway/model. Binary/base64 outputs are normalized to PNG before storage.

For local development only, set `IMAGE_DEBUG=true` in `.env.local`. The server logs the final prompt, provider and model ID, rough token estimate, reference count, context-source names and the parameters actually sent. It never logs keys, authorization headers or image bytes. This is disabled in production even if the variable is set. Prompt logs can contain private brand and post data, so use them only in a trusted local terminal and turn the flag off afterward.

New carousel AI output must include at least three slide prompts. Historical carousels without slides remain intact; they need a user-approved content regeneration or manual slide editing to gain slide-specific direction. No database migration is needed for this validation change.

The image adapter tests use synthetic provider responses. They verify request shapes and storage normalization, not aesthetic quality. A controlled before/after comparison must use the same real post, image model, seed if supported, and reference assets; it requires a valid workspace provider token and incurs provider usage.

The opt-in `src/lib/ai/__tests__/image-quality.live.test.ts` reads one saved post and its configured workspace model. Set `RUN_LIVE_TESTS=true` and `RUN_LIVE_IMAGE_COMPARISON=inspect` to write the old and new prompts plus a secret-free request summary under `artifacts/image-quality/` without generating an image. Set `RUN_LIVE_IMAGE_COMPARISON=true` for the two real provider requests and local before/after image files. The latter is billable and fails honestly if the provider quota is exhausted. The local artifact directory is git-ignored.
