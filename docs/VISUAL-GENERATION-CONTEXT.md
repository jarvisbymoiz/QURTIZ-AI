# Visual generation context pipeline

The shared visual brief receives the saved post topic, hook, platform caption, relevant copy, CTA, Brand Brain name/description, products/services, audience/tone, visual identity, restrictions and saved visual preferences. Caption context is bounded at 6,000 characters; it is reference material, not instructions to render every sentence on the image. Explicit authored wording and text-free concepts remain authoritative. A vague visual concept is expanded creatively within verified brand facts.

Brand attachments travel as actual image pixels, not filenames alone. The selected set is the latest active logo, latest active avatar/profile picture and every active design reference in saved upload order (created time ascending, with ID as a stable tie breaker). Roles remain distinct as logo, profileAvatar and designReference in preparation and queued job metadata. Numbered attachment labels in the brief match pixel order. Local/companion transport retains the combined 4MB binary budget, without a four-file truncation. Oversized/unsupported sets fail clearly rather than silently dropping files. Missing attached files also fail clearly. PDF or arbitrary brand documents are not image references.

Both direct local image requests and cloud companion claims preserve all selected references. Cloud URLs are signed, short-lived, checked against the authenticated workspace and resolved only by the paired companion. No OAuth credentials are sent with the prompt. The companion uses image edits when references are present and ordinary image generation when absent. Existing upload, completion, PNG normalization and visual persistence flows remain intact.

Logo references are supplied for integration into the generated design. The model chooses placement to fit the composition while preserving the supplied logo's identity and proportions. AI generation and companion persistence do not add a fixed logo overlay afterward. Studio template and bulk-template generation also no longer automatically insert the uploaded logo. Avatar likeness is used only when relevant to the selected concept. Model-rendered logo fidelity needs human review and is not guaranteed. Previously saved images retain their baked-in artwork until regenerated.

Validation includes multi-reference request serialization, cloud-worker reference download/forward/upload/completion, brief context, authentication and pairing tests. These tests use controlled fixtures; they do not prove the aesthetic quality of a live ChatGPT generation.

Deployment requires updating Qurtiz and the companion worker together. An already installed companion uses its installed copy of `cloud-worker.mjs` until updated/restarted. These source changes do not by themselves update the running Production site or the installed companion.


## Reference pipeline verification — October 10, 2026

Root causes were the two-design loader limit/reversed ordering, the OpenAI-compatible adapter using only references[0], a four-reference cloud-claim truncation, and the older installed Companion forwarding only job.references[0]. The prepared payloads also lost role metadata. These have been corrected. Saved reference MIME is verified against decoded pixels, and storage paths must belong to the selected workspace.

API formats: Gemini receives every inlineData image. OpenAI-compatible edits send one image field or ordered repeated image[] fields; an edits rejection is returned honestly rather than falling back to text-only generation. Cloudflare discovers available native image slots from the configured model schema and rejects insufficient capacity before generation. OpenRouter uses its native /images API with ordered input_references, discovers the configured model endpoint's actual reference limit, and pins a capable endpoint without a fallback that could discard references. No model is hard-coded. Reference-free generation remains supported.

Diagnostics contain mode, counts by reference role, total references and non-sensitive request controls. Prompts, pixel data, signed/private URLs and credentials are excluded. IMAGE_DEBUG=true enables API diagnostics outside production; local/cloud transport diagnostics are development-only.
