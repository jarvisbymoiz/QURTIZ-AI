# Content creation entitlement

All AI content creation paths (Chat Agent, Content Studio, Bulk Create, and Auto Run) call `generateAndPersistContent`. That service checks one workspace-scoped entitlement before requesting a text model and again under a PostgreSQL advisory transaction lock before inserting a post. Only persisted `content_items` count as usage. Failed provider calls and retry attempts do not.

Until a billing plan defines a content allowance, a missing `settings` row with key `content_creation_entitlement` means **unlimited**. The `free` value in `workspace_storage_quotas.plan` currently governs storage and does not imply a content-creation limit. To configure an explicit workspace limit, set that settings JSON to, for example, `{ "limit": 100, "period": "month" }` through an authorized administrative process. Supported periods are `day`, `month`, and `lifetime`; UTC determines window boundaries. `limit: null` means unlimited and `limit: 0` intentionally disables creation. Malformed explicit limits fail closed with a configuration error. Limits count all successfully saved posts, including subsequently soft-deleted posts, so deletion cannot restore spent allowance.

An AI provider's token/rate/billing quota is separate from Qurtiz's content allowance. The Chat Agent tool returns `AI_PROVIDER_RATE_LIMIT` with `quota.source = "ai_provider"` and provider/model/window details when available. A Qurtiz limit returns `CONTENT_QUOTA_EXHAUSTED` with `quota.source = "workspace_settings"`, `limit`, `used`, `remaining`, `period`, `resetAt`, and the storage plan for context. Neither failure creates a post. Use `node scripts/audit-content-quota.mjs` for a read-only live-database audit; it reads `.env.local` and does not print credentials.
